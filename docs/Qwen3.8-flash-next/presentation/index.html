05 · Qwen Sparse Attention

Block-level Indexer 选候选，Sparse Core 做精确 Attention

INDEXER + CORE

Indexer 只构造 sparse mask；QSA 的 value aggregation 仍由标准 softmax attention 完成。

Block key：连续 4 个未加 RoPE 的 raw K 取均值并 RMSNorm，再使用 block 起点 position 施加 Partial RoPE。
Indexer score：4 个 query heads 计算 。
Selection：最多选择 512 个完整 block，展开为最多 2048 个 token；不完整 causal tail 始终保留。
Sparse Core：24Q / 2KV GQA 在 上计算精确 softmax。

05 · QSA Training

Indexer 先 dense distillation，再切换到 sparse CPT

TWO-STAGE CPT
Stage 1
Dense DistillationFull Attention 多头概率 → token relevance → 4-token MaxPool → all-block KL。只更新 Indexer。
↓ 先建立 block-level relevance，再切换到 TopK mask
Stage 2
Sparse Joint TrainingLM loss 让 backbone 适应 TopK 上下文；selected-block KL 继续校准 Indexer。

LM loss 可更新被选中的 sparse attention 路径，但梯度不能穿过离散 TopK 改变候选集合。

Stage 1：1,000 steps，8×256K tokens/step，约 2B tokens，。
Stage 2：8,000 steps，96×256K tokens/step，约 200B tokens，。
Selected-block KL：Stage 2 只对已选 block 校准分数；未选 block 当步没有直接监督。

07 · N-gram Embedding

16 个地址并行查表，concat 为 2560-d PLE embedding

HASH + LOOKUP

Addressing 完全确定且不可学习；反向传播只更新本 batch 实际命中的 embedding rows。

Head layout：8 个 bigram heads + 8 个 trigram heads；每个地址返回 160-d row。
Tuple mixing：固定 seed 经 SplitMix64 产生 position-specific odd multipliers；token id 乘法结果按位 XOR。
Multi-mod hash：mixed id 分别对 8 个不同 prime table sizes 取模；碰撞需要在多个 head 上同时对齐才会完全混淆。
Storage：物理矩阵为 ；BF16 约 95.4 GiB，常驻 host memory 并做异步 prefetch。
Source: Transformers Qwen4-Exp reference implementation; official checkpoint config

07 · PLE Injection

PLE：token-local branch gate + dilated depthwise Conv1d

DILATED DWCONV

Direct path 不再沿 T 维 mixing；卷积分支在门控后的 U 上增加稀疏局部 receptive field。

Token-local gate：由 得到 Q、由 得到 K；二者只在同一位置、同一 branch 做点积，没有 softmax。
Shared value：4 个 branch 使用同一 ，但分别乘 。
Dilated taps：输出 读取 ；最大回看距离为 9。
Depthwise：10240 个 channel 各自拥有 4 个 temporal weights，不在 branch / hidden channel 之间做 mixing。
Initialization：conv weights 为 0，所以初始前向只有 direct U；该局部分支由训练逐步打开。

分析计算量、cache 或梯度路径时，应先确认讨论的是哪一种 state。

GDN state：大小与 context length 无关，但它是有损的 prefix summary。
QSA KV：仍保留 token-level K/V；稀疏化降低每个 query 实际访问的候选数。
PLE table：增加参数容量但不增加 backbone hidden width；只对命中 rows 产生梯度。
GR state：沿 depth 传播 4d residual，不是时间递推 cache。
